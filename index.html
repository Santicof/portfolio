01 / Sobre mí

Backend de día, IA siempre, docente por vocación.

Soy Licenciado en Sistemas por la Universidad Nacional de Lanús y trabajo como Backend Developer .NET en el equipo de Cloud & Data de Andreani, uno de los grupos logísticos más grandes de Argentina. Entré en 2023 como Analista DevOps automatizando despliegues en Azure y OpenShift, y hoy desarrollo los microservicios que modelan la base del flujo logístico: unidades operativas, zonas geográficas y la geolocalización de envíos.

En paralelo construyo productos propios: sistemas de turnos en producción para consultorios reales y sistemas multi-agente con LLMs que analizan código, proponen fixes y los validan con tests. Me interesa la IA aplicada con criterio de ingeniería: salidas estructuradas, reglas auditables y validación real.

Además soy docente universitario en materias de programación y habilidades blandas, y divulgo tecnología en San Sistemas, con reels y el podcast “De Informáticos Para Informáticos”.

    E-commerce AI Agent System: dos agentes que detectan, corrigen y deciden

    Sistema multi-agente que analiza el código de un equipo de e-commerce, detecta bugs, genera un fix, lo valida corriendo pytest y decide si el cambio puede avanzar. Reemplaza una revisión manual de 15–30 minutos por un análisis de 7–15 segundos (menos de 0,1 s con caché).

    Archivo .pyCLI, API REST o frontend
    Orchestratorcoordina y acumula contexto, ~50 líneas de Python puro
    BugDetectorAgentLLM detecta → LLM genera fix → pytest antes/después
    GateAgentreglas determinísticas + LLM que explica la decisión
    Veredictogo / warn / no-go
    auth.py → BLOCKcart.py → WARNutils.py → APPROVE
    • Salida estructurada con JSON mode + Pydantic: el schema se valida aunque el LLM varíe.
    • Fallback automático de Llama 3.3 70B a Llama 3.1 8B ante rate limit (degradación controlada).
    • Caché por hash de contenido, no por nombre: si el archivo cambia, se invalida sola.
    • Sin LangChain ni CrewAI a propósito: cada paso es visible, debuggeable y defendible.
    • Alternativa Ollama local documentada para código que no puede salir de la empresa.
    • Tres interfaces: CLI, API REST con Swagger y frontend React. Suite de más de 16 tests con bugs expuestos a propósito como escenarios de demo.

    Lo crítico no depende del LLM

    Las reglas que bloquean un merge son determinísticas y auditables. El modelo explica la decisión, no la toma.

    Validar con tests, no con fe

    Un fix generado solo vale si los tests pasan. La validación corre aparte del modelo.

    Contratos estrictos

    JSON mode, schemas con Pydantic y prompts con los tests como contexto para obtener respuestas predecibles.

    Costo, latencia y privacidad

    Modelo de fallback, caché y opción local con Ollama: cada tradeoff está explícito y documentado.

    Agentes y RAG
